1. Resumen ejecutivo
Trazaap es un MVP funcional parcial, con una base técnica real en Next.js, Express, PostgreSQL y Hyperledger Fabric.
No es una simulación puramente local: existe una red Fabric configurable, Gateway SDK, chaincode propio, envío de
transacciones y consultas al ledger. Sin embargo, el alcance real es considerablemente menor que el afirmado en varias
secciones de los documentos académicos.

3. Estado de la integración blockchain
Clasificación global: REAL PERO PARCIAL
El backend utiliza @hyperledger/fabric-gateway, envía transacciones y consulta chaincode. La red no tiene la topología,
resiliencia, segregación ni consistencia descritas académicamente.
Flujo técnico real
1. El endpoint recibe una solicitud autenticada.
2. El repository guarda primero el registro en PostgreSQL.
3. El service consulta PostgreSQL para construir un payload canónico.
4. El backend calcula SHA-256 localmente y el chaincode vuelve a calcularlo.
5. FabricTraceabilityService.registrarEvento() ejecuta submitAsync('registrarEvento').
6. Espera el commit mediante getStatus().
7. Obtiene transactionId y blockNumber.
8. El chaincode almacena payload, hash, actor, fecha, timestamp Fabric y txId.
9. El resultado se devuelve por HTTP, pero no se conserva en PostgreSQL.
Evidencia: blockchain.service.js:93-125; fabric-traceability.service.js:71-98;
fabric/chaincode/traceability/index.js:7-40; validación posterior en líneas 43-72; reconstrucción desde
PostgreSQL en trazabilidad.service.js:133-198.

Consistencia PostgreSQL–Fabric
Si PostgreSQL guarda y Fabric falla, fabric.client.js:3-24 convierte el error en estado PENDIENTE. El registro
operativo continúa guardado, pero el pendiente, error e intentos no se almacenan; no hay outbox, cola, reintento o
reconciliación.
Si Fabric guarda y falla una operación PostgreSQL posterior, tampoco existe compensación ni transacción distribuida. El
txId y número de bloque se obtienen en memoria en fabric-traceability.service.js:91-97, pero no se persisten.
Limitaciones de auditabilidad
• Todos los eventos se firman con la misma identidad Fabric administrativa.
• El usuario de negocio es texto, no identidad X.509 individual.
• El chaincode no valida roles o identidad del invocador.
• registrarEvento permite sobrescribir la clave y marca ACTUALIZADO.
• El historial existe en el ledger, pero no se expone GetHistoryForKey.
• Un peer y un orderer no aportan tolerancia a fallos real.
• No existe evidencia runtime reproducible de una transacción ya ejecutada en el repositorio.
